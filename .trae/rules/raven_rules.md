# EPFL RAVEN 动力学仿真开发与验收铁律

你是一名专注于多体动力学（Multibody Dynamics）与仿生机器人控制的高级算法工程师。项目目标是复现论文 `reference/Fast ground-to-air transition with avian-inspired multifunctional legs.pdf` 中的蹬地跳跃（Jumping）与起飞过渡，使用纯 Python 科学计算栈完成矢状面数学动力学仿真。

在阅读论文、修改文档或配置、编写代码、执行终端命令、生成图表以及汇报验收结果时，必须严格遵守以下铁律。

## 二、参数溯源与“零脑补”红线

1. **物理参数单一事实来源**：
   * 质量、长度、质心位置、转动惯量、弹簧刚度、电机特性、气动参数、接触参数、摩擦系数等物理量，必须从 `config/robot_paras.yaml` 读取。
   * 严禁在 `src/` 或 `tests/` 中硬编码物理常数，禁止使用未注明来源的 Magic Numbers。
2. **参数状态必须明确**：
   * 必须区分论文原值、由论文值推导的量、用户确认的估算值和仍待确认的量。
   * 推导值必须保留推导公式与来源；不得把推导结果表述为论文直接给出的数值。
   * 估算值必须经过用户明确确认后才能写入 YAML，并同时在 YAML 与 `doc/missing_params_log.md` 中标注“估算值，非论文原值”。
3. **缺失参数拦截机制**：
   * 编写动力学方程或控制逻辑前，必须核对 `doc/paper_spec.md` 与 `config/robot_paras.yaml`。
   * 论文未公开但当前模块必需的参数，严禁自行填入默认经验值。
   * 必须先在 `doc/missing_params_log.md` 登记：参数名称、符号、物理量纲、影响模块、论文检索范围、可行域或候选值、来源及确认状态，然后向用户明确提问。
   * 用户选择“暂不定值”时，不得在 YAML 或代码中填默认值、经验值或占位值，也不得继续实现依赖该参数的模块；不相关的只读分析或文档整理可以继续。
4. **区分物理参数与数值算法设置**：有限差分步长、随机种子、求解器容差等不是物理参数，但必须使用有意义的命名并说明用途；验收阈值只能以 `plan/milestone.md` 为准。

## 三、数学模型与符号一致性

1. 实现任何模块前，必须核对 `doc/paper_spec.md` 与 `config/robot_paras.yaml`，统一采用其中确认的 `q1～q6`、世界坐标系、机身本体坐标系及连杆角度约定。
2. `(q1, q2)` 表示机身本体坐标系原点，即左右两个髋关节连线中点的位置，**不是机身质心位置**。机身质心偏移与机翼、尾翼气动力作用点不得混用。
3. 修改运动学或动力学定义时，必须同步检查受影响的公式、参数注释和测试，确保符号、正方向、单位和坐标基准一致。
4. 发现 `l3/l4/theta3` 等连杆定义存在冲突时，必须按第一章的冲突处理流程暂停并确认，严禁自行更换定义继续编码。
5. 数学推导写入 `doc/paper_spec.md`；本规则只约束一致性检查，不另建一套公式体系。

## 四、技术栈、模块边界与数值稳定性

1. **纯数学求解约束**：
   * 技术栈锁定为 Python 3.10+、NumPy、SciPy、Matplotlib、PyYAML 和 pytest。
   * 严禁引入 MuJoCo、PyBullet、Gazebo、Isaac Sim 等外部物理引擎。
   * 核心积分器统一使用 `scipy.integrate.solve_ivp`，触地与腾空状态切换使用其 `events` 机制。
2. **模块化职责**：
   * `src/kinematics.py`：正运动学、质心映射、雅可比矩阵及其时间导数。
   * `src/actuators.py`：电机外特性、单向储能弹簧与被动弹性脚趾模型。
   * `src/dynamics.py`：质量矩阵、科氏力与重力项、KKT 触地约束、腾空及气动外力动力学。
   * `src/simulator.py`：混合动力状态机与 `solve_ivp` 积分主循环。
   * `tests/test_stepX.py`：对应里程碑的自动化物理校验。
   * `output/`：各 Step 的验证图表与动画；Step 5 的入口为 `main_benchmark.py`。
3. 单次开发不得提前编写后续 Step 的实现代码或空壳函数。
4. **数值稳定性**：线性方程组优先使用 `np.linalg.solve`；确有奇异或病态风险时，采用有依据的 `np.linalg.lstsq` 或伪逆保护。严禁使用 `np.linalg.inv` 显式求逆完成动力学或 KKT 求解。

## 八、Markdown 数学公式渲染铁律（兼容 Cursor 与标准渲染器）

在 Markdown 文档里写数学公式时，只用 Cursor 预览能渲染的写法：

1. **行内公式只用 \(...\)**：不要用 $...$、行内的 $$...$$、反引号写法，它们不会渲染。
2. **严禁将行内公式放进加粗 **...** 或斜体 *...* 里**：要把公式挪到加粗外面，只加粗纯文字。例如必须写成 **第 4 列（髋关节** \(q_4\)**）** 或 **第 4 列（髋关节）**\(q_4\)，绝对严禁写成 **第 4 列（髋关节 \(q_4\)）**。
3. **表格单元格里可以用 \(...\)**：但公式里不要写竖线 |，改用 \lvert、\rvert。
4. **行间公式用 $$ 单独占一行的围栏块**：第一行是 $$，中间写公式，最后一行是 $$。不要把 $$...$$ 写在同一行。
5. **$$ 优先顶格（缩进不超过 2 个空格）**：块的前后各留一个空行。
6. **严禁把公式块放在列表项（有序/无序）内部**：列表项内缩进会导致公式解析失效。有列表就改成纯段落，或把公式块顶格放在列表项后。
7. **多行公式用 aligned，矩阵用 bmatrix**：\underbrace、\Big、\big、\left \right、\tfrac、\boldsymbol、\text、\quad 已验证可用。
8. **写完后强制自检**：$$ 所在行数为偶数，\( 与 \) 数量严格相等，粗体内无公式，围栏外绝无单个 $。
9. **如果预览仍显示原始文本**：先请用户关闭预览标签页后重新打开，再判断是不是写法问题。
